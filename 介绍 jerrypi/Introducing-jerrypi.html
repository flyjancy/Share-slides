01 · 为什么做

One extension is the whole setup

起因是一台什么都不许装的 Windows 工作机 —— 但省事的不止这一台。

01不装环境目标机不用装 Node —— 扩展宿主自带 Node 24
02开箱即用pi 的 SDK bundle 随扩展分发，面板与工具卡片装完就有
03一份配置与 pi CLI 共享 ~/.pi/agent，会话两边互通
唯一被允许的安装方式，逼出了最省事的安装方式。

02 · Pi 的优势

Why Pi: simple, controllable, hackable

A简单

一个 npm 包、零原生依赖；配置就是 ~/.pi/agent 下几个 JSON 文件。

B可控

模型、工具、审批门槛全是自己的设置；会话是纯 JSONL，可审计可迁移。

C好懂

文档与源码齐全，行为可预测 —— 出问题能顺着查到根因。

D可扩展

TypeScript 扩展、SDK、主题；这个 VS Code 扩展本身就是用 SDK 拼出来的。

能用 SDK 拼出一个 IDE 扩展，就是可扩展性最好的证明。

03 · 经验教训（一）

Same names, silent traps

01名同义异sessionDir 是直接放 .jsonl 的那层目录 —— 差一层就没影
02路径分叉物理路径与逻辑路径没对齐，同一个目录变成两个
03越权删除logout() 会删掉用户 auth.json 里自己的凭据
04静默跳过无凭据时刷新模型列表，一次请求都不发
这些代价全是静默的 —— 所以只读源码，不猜语义。

03 · 经验教训（二）

Assertions that can go red

01每步先写断言、看红、再实现 —— 编译不过、模块不存在，都不算红。
02断言要独立于被测实现：隔离目录起测，或直接问另一份实现当 oracle。
03SKIP 不是 PASS —— 静默跳过必须和「真的没有」区分得开。
每次改动自动跑 329 条 host-check 与 16 项 gating self-test；验收挂了就再来一轮。
假绿比红贵 —— 它让你以为已经验证过了。
