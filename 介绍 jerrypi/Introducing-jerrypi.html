Why Pi: simple, controllable, hackable

A简单

一个 npm 包、零原生依赖；配置就是 ~/.pi/agent 下几个 JSON 文件。

B可控

模型、工具、审批门槛全是自己的设置；会话是纯 JSONL，可审计可迁移。

C好懂

文档与源码齐全，行为可预测 —— 出问题能顺着查到根因。

D可扩展

TypeScript 扩展、SDK、主题；这个 VS Code 扩展本身就是用 SDK 拼出来的。

能用 SDK 拼出一个 IDE 扩展，就是可扩展性最好的证明。

Write it down before you build it

01文档先行目标、判据、阶段先写成文档，再动手写代码
02单一来源同一件事只留一份文档 —— 复制出来的副本一定会烂掉
03状态明确每次提交前更新「现在在哪 / 欠什么 / 下一步」
agent 的上下文有限 —— 只有写进文件的东西留得住。

Get it reviewed, then prove it

01多轮 review：同一个模型看不出自己的盲区 —— 换一个更强的模型当评审。
02评审意见先复现再采纳：把它当成一条新断言跑一遍，绿不了就不采纳。
03规范验收：先写断言、看红、再实现；SKIP 不是 PASS；人工验收固定四类。
每次改动自动跑 329 条 host-check 与 16 项 gating self-test；验收挂了就再来一轮。
假绿比红贵 —— 它让你以为已经验证过了。
